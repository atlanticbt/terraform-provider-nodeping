# Security policy

## Supported versions

Security fixes are released for the latest minor version. Upgrade to the newest
release before reporting, in case the issue is already fixed.

## Reporting a vulnerability

Report vulnerabilities privately through GitHub: open the repository's
**Security** tab and choose **Report a vulnerability**. Do not open a public
issue or pull request for a security problem.

Include:

- the provider version and the OpenTofu or Terraform version
- what an attacker can do, and what they need to do it
- steps or configuration that reproduce it, with any real values removed

**Never include a NodePing API token, account ID or contact details in a report,
issue, log or example.** Replace them with placeholders. If you have exposed a
token, revoke it in NodePing first.

## What to expect

A maintainer acknowledges the report within three business days and keeps you
informed while it is investigated. Fixes are released as a new version and
described in a GitHub security advisory, crediting the reporter unless you ask
otherwise.
