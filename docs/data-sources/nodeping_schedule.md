# nodeping_schedule (Data Source)

Fetches a NodePing notification schedule by ID.

Schedule IDs are chosen by whoever created the schedule rather than generated by
NodePing, so the ID is simply the name it was given — `BusinessHours`,
`AfterHours`, and so on.

## Example Usage

```hcl
data "nodeping_schedule" "business_hours" {
  id = "BusinessHours"
}

output "monday_window" {
  value = "${data.nodeping_schedule.business_hours.monday.time1}-${data.nodeping_schedule.business_hours.monday.time2}"
}

# Days that are not scheduled come back null.
output "weekend_is_quiet" {
  value = data.nodeping_schedule.business_hours.saturday == null
}
```

### Looking Up a SubAccount Schedule

```hcl
data "nodeping_schedule" "client_hours" {
  id          = "ClientHours"
  customer_id = "201205050153W2Q4C"
}
```

## Argument Reference

- `id` - (Required) The schedule name.
- `customer_id` - (Optional) The customer ID (SubAccount ID) to look the schedule
  up under. Omit to use the account the provider is configured for.

## Attribute Reference

- `customer_id` - The customer ID that owns the schedule, when the API reports
  one.
- `monday`, `tuesday`, `wednesday`, `thursday`, `friday`, `saturday`, `sunday` -
  The notification window for that day, or `null` when the day is unscheduled.
  Each contains:
  - `time1` - Start of the span, 24-hour `H:MM` or `HH:MM`.
  - `time2` - End of the span.
  - `exclude` - Whether the span is inverted (notify all day except the span).
  - `disabled` - Whether notifications are disabled for the day.
  - `allday` - Whether notifications run all day.

A schedule that does not exist is an error, not an empty result.
